Setup

Prerequisites

  • Python 3.10+, 8 GB RAM, no GPU required (Phases 1–2)
  • Phase 1 LLM demos: an OpenAI-compatible endpoint key (OPENAI_API_KEY + OPENAI_BASE_URL=https://api.openai.com/v1)
  • Phase 3: Modal account (pip install modal && modal setup) for L4 GPU (~$0.5–1/group)

Install

git clone -b tutorial-rebuild https://github.com/syaikhipin/kdd26-memdiag kdd-tutorial
cd kdd-tutorial
pip install numpy matplotlib pyyaml # offline deps
pip install -e source # CLI package (memory-diagnostic-toolkit)
pip install -e "source[api]" # + openai/tiktoken for LLM demos
python -m compileall -q source # sanity check

Open any notebook in Colab or locally — each auto-clones + installs:

Phase 4 — Cognitive Memory Layer (1 notebook, offline)

Build a pure-Python "CML-lite" provider that adds constraint awareness — surfacing a stored rule (“I’m allergic to shellfish”, “depth 16 → OOM”) even on zero-overlap queries — then diagnose it with the 3-probe harness from Phase 2. Inspired by the Cognitive Memory Layer (avinash-mall/CognitiveMemoryLayer); its full stack (Docker + Neo4j + ~25 GB of models) cannot run in Colab, so we capture the cognitive core in ~90 lines of pure Python.

Memory Diagnostic (Phase 3D)

Interventional probes with a real LLM agent (frozen pre-decision snapshots). 5 memory conditions:

ConditionOOM proposal rateWhat it tests
M0 no-memory50%Placebo baseline
M1 raw-history12%Full trial log
M2 retrieved (same-batch)12%Batch-keyed retrieval
M3 structured-rule5%Raw + inferred constraint
M4 oracle0%Raw + actual outcome

Key finding: any history cuts OOM proposals by 76%. Naive retrieval filtering is counterproductive (any-OOM increases 12%→30%). Structured rules approach oracle performance.
